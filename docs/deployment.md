# Deployment

No deployment has been performed. The target is a low-traffic $0/month demonstration on Cloudflare Pages Functions (the Workers runtime) and D1 with provider subdomains. Never enable billing or paid resources without explicit owner approval. Wrangler is authenticated to the owner's email, but the OAuth token lacks Billing Read: a read-only subscription lookup returned HTTP 403. The account's Free plan still needs dashboard confirmation before provisioning.

As checked on 2026-11-11, [Workers Free](https://developers.cloudflare.com/workers/platform/limits/) lists 100,000 requests/day and 10 ms CPU time per request. [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/) lists 5 million rows read/day, 100,000 rows written/day, and 5 GB total storage. [Cloudflare's September 2026 notice](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/) says D1 requests fail when daily free row limits are reached. These limits can change; recheck them before deployment and do not promise uptime or unlimited usage.

Optional [Workers AI Free](https://developers.cloudflare.com/workers-ai/platform/pricing/) currently includes 10,000 Neurons/day. Some models require a paid billing method; this project allows only two listed JSON-capable Llama models in its AI route. No AI binding is configured in the checked-in Wrangler files. Adding `[ai]` with `binding = "AI"` requires the owner's Cloudflare authorization. Even local inference consumes the account's AI allocation, so do not enable or exercise it without checking the plan and consent. The no-key mode remains usable when AI is unavailable.

The checked-in `wrangler.toml` intentionally uses a placeholder database ID and a local `ALLOWED_ORIGIN`. **Replace both with verified production values before deploying.** Keep the Pages app and API on the same origin so owner cookies work. Set `OWNER_USERNAME` and `OWNER_PASSWORD_HASH` as protected deployment secrets; never copy `.dev.vars` into Git. Configure the Pages D1 binding as `DB`, apply the SQL migrations to the intended remote D1 database, and seed only fictional data. The current local owner setup script is for local development; production secret setup needs an owner-approved procedure.

Deployment requires the owner's Cloudflare authorization, production configuration, D1 migration, fictional seed data, HTTPS checks, a booking flow test, and a safe owner experience. Visitor writes need reset or isolation before publication. The public demo must not send real messages. Record verified URLs and exact deployment commands here only after they exist.
