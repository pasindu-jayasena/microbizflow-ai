# Deployment

The [deployment readiness report](deployment-readiness.md) records verified checks and free-tier limits. The [final deployment plan](deployment-plan.md) specifies the exact resources and release sequence. Cloudflare provisioning and deployment await the owner's approval of that plan.

No deployment has been performed. The target is a low-traffic $0/month demonstration on Cloudflare Pages Functions (the Workers runtime) and D1 with provider subdomains. Never enable billing or paid resources without explicit owner approval. `node scripts/wrangler.mjs whoami` confirmed the account associated with `pasindujayasena.biz@gmail.com` on 2026-11-11. On 2026-11-11, the owner reported checking the Billing dashboard and confirmed Workers Free active, R2 Paid canceled, no other paid developer subscriptions, $0.00 outstanding balance, and no unpaid invoices or unexpected usage. The Wrangler token lacks Billing Read (HTTP 403), so the dashboard result is owner-reported rather than independently verified by API.

As checked on 2026-11-11, [Workers Free](https://developers.cloudflare.com/workers/platform/limits/) lists 100,000 requests/day and 10 ms CPU time per request. [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/) lists 5 million rows read/day, 100,000 rows written/day, and 5 GB total storage. [Cloudflare's September 2026 notice](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/) says D1 requests fail when daily free row limits are reached. These limits can change; recheck them before deployment and do not promise uptime or unlimited usage.

Optional [Workers AI Free](https://developers.cloudflare.com/workers-ai/platform/pricing/) currently includes 10,000 Neurons/day. Some models require a paid billing method; this project allows only two listed JSON-capable Llama models in its AI route. No AI binding is configured in the checked-in Wrangler files. Adding `[ai]` with `binding = "AI"` requires the owner's Cloudflare authorization. Even local inference consumes the account's AI allocation, so do not enable or exercise it without checking the plan and consent. The no-key mode remains usable when AI is unavailable.

The checked-in `wrangler.worker.toml` intentionally uses a placeholder database ID and a local `ALLOWED_ORIGIN`. **Replace both with verified production values before deploying.** Keep the Pages app and API on the same origin so owner cookies work. Set `OWNER_USERNAME` and `OWNER_PASSWORD_HASH` as protected deployment secrets; never copy `.dev.vars` into Git. Configure the Pages D1 binding as `DB`, apply the SQL migrations to the intended remote D1 database, and seed only fictional data. After plan approval, `npm run owner:prepare:production` generates an ignored 256-bit production password and a salted fast hash for Workers Free. Save the password privately and delete the local credentials file after verifying sign-in.

Both checked-in Wrangler configs set `DEMO_MODE = "true"`. The server also defaults to demo mode if the variable is missing. This rejects real-looking booking contacts, accepts only reserved `@example.invalid` addresses, stores a fixed fictional name, and discards booking notes. Keep the flag true for a public portfolio demo. A real customer deployment would need a separate privacy, billing, and security review before setting it false.

The owner can run age-based cleanup manually. [Workers Free limits](https://developers.cloudflare.com/workers/platform/limits/) list up to five Cron Triggers per account and 10 ms CPU time for a Cron Trigger. The checked-in standalone Worker config declares one hourly UTC Cron Trigger for bounded demo reservation reset, reminder preparation, workflow recovery, webhook recovery, and retention of one customer and 10 unbooked analyses per run; no Worker or trigger has been deployed. The reset processes at most two reservations older than 24 hours per run and invalidates their private codes. Its `workers_dev = false` and `preview_urls = false` settings keep the scheduler off public Worker and preview URLs. The Pages Function wrapper does not run the scheduled handler. Deploying the separate Worker with the same approved D1 binding and measuring its actual CPU use remain part of the deployment-readiness review.

Deployment requires the owner's Cloudflare authorization, production configuration, D1 migration, fictional seed data, HTTPS checks, a booking flow test, and a safe owner experience. The scheduled reset strategy must be enabled and verified for a writable public demo. The public demo must not send real messages. Record verified URLs and exact deployment commands here only after they exist.

The inbound webhook remains disabled unless a server-only `WEBHOOK_SECRET` is explicitly configured. A public demo does not need this secret; no external sender or paid integration is required. The owner dashboard can still show its disabled state. Do not copy the synthetic local test secret into production.

CRM activity is mock-only in the checked-in build. It needs no external API key, subscription, or billable provider. Do not configure a real CRM or messaging integration for the public demo without a separate readiness review and explicit authorization.
